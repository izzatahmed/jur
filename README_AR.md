# UJORH — الإصدار 3.2: تحسين النزاهة وسير التحكيم العلمي

**تاريخ الإصدار: 24 نوفمبر 2026**  
**الحالة: نموذج عرض تفاعلي + مكوّن اختياري للتحرير الخاص غير منشور.**

هذا تحديث موجّه إلى `editorial-demo` والمحرّر الخاص الاختياري، **وليس تحديثًا للواجهة الرئيسية**. لا يستبدل الإصدار 3.1.6، ولا يعدّل ملفات نشر الأبحاث `publications`، ولا ملف `docs/config.js`، ولا عامل الاستقبال القائم `worker`، ولا مستودع `jus`.

## أولا: ماذا أُنجز؟

1. **ترقيم العرض واسترجاع المخطوطات (في المكوّن الخاص فقط):** لم يعد العامل يقتصر على أول 18 مجلدًا. يعرض 10 سجلات في الصفحة افتراضيًا، مع أزرار السابق والتالي وعدد السجلات المفهرسة، ويعتمد الترتيب التنازلي على التاريخ المضمّن في رقم الاستلام. ترتيب سجلات اليوم الواحد ليس مضمونًا بالدقة الزمنية. **حد GitHub الرسمي 1000 إدخال لكل مجلد**؛ عند بلوغه يتوقف النظام برسالة واضحة بدل إخفاء السجلات، ويستلزم الانتقال لاحقًا إلى قاعدة بيانات أو مخزن مؤسسي.
2. **قواعد الاعتماد العلمي:** تصنيف البحث الآن «مرشح لاعتماد أولي» فقط، وليس اعتمادًا علميًا حقيقيًا. يتطلب تسجيل الفحص الأولي واثنين من تقارير الجولة الحالية لمراجعين مختلفين سبق تسجيل تعيينهما، وأن تتضمن جميع التقارير توصية صريحة بالقبول دون ملاحظة حرجة. توصية «تنقيح» أو «رفض» تمنع الترشيح حتى لو كانت الدرجات مرتفعة.
3. **الجولات والتعديلات:** طلب التنقيح يفتح جولة جديدة؛ يجب توثيق استلام نسخة معدلة مع وصف مراجعتها، ثم إعادة الفحص والحصول على تقريرين جديدين. لا تشكل هذه الخطوة وحدها تحققًا من صحة الملف المعدّل.
4. **سجل الأحداث:** يحفظ اسم صاحب الفعل التحريري، والتوقيت UTC، والانتقال من الحالة السابقة إلى الجديدة، ورقم الجولة، ورقم الحدث المتسلسل. في التطبيق الخاص تُحفظ السجلات ضمن `editorial.json` في مستودع `jus`، ويمكن متابعة تعديل الملف عبر تاريخ GitHub. **السجل ليس دفترًا مشفّرًا غير قابل للتعديل.**
5. **تقييم متعدد الأبعاد:** موثوقية الدليل = 40% منهجية + 40% موثوقية الأدلة + 20% قابلية إعادة الإنتاج. المساهمة العلمية = 50% أصالة + 50% أهمية. قيمة التأثير اللاحق والاستشهادات منفصلة عن الموثوقية. هذه الأوزان **افتراضية لأغراض التجربة**، ولا تصلح اعتمادًا موحدًا لكل التخصصات دون دراسة تحقق ومعايير تخصصية.
6. **اختبارات:** 19 اختبارًا آليًا ناجحًا على قواعد التقييم، الجولات، الوقف التحريري، منع اعتماد توصيات التنقيح، الهوية الموثقة بالـJWT الاختباري، وترقيم 37 مخطوطة افتراضية. لم يكتمل اختبار متصفح تفاعلي داخل البيئة بسبب قيود تشغيل المتصفح؛ لذلك يلزم فحص واجهة الهاتف والحاسوب بعد رفع ملفات العرض.

## ثانيًا: التركيب الآمن للعرض العام — الآن

1. احتفظ بنسخة الاحتياط الموجودة لديك من `jur`؛ واحتفظ أيضًا برقم الـcommit الحالي.
2. فك ضغط **حزمة العرض العام** `UJORH_v3.2_Public_Editorial_Update.zip`.
3. ارفع مجلد `docs/editorial-demo/` **بمحتوياته إلى الموقع المناظر في `jur`**، مستبدلًا ملفات `editorial-demo` القديمة فقط. يجب ألا ينشأ مجلد إضافي `docs/docs`.
4. اترك بقية ملفات `jur` كما هي تمامًا، وخصوصًا:
   - `docs/index.html`, `docs/config.js`, `docs/assets/`, `docs/publications/`
   - `worker/` وملفات Cloudflare الحالية.
5. افتح بعد اكتمال تحديث GitHub Pages:
   `https://izzatahmed.github.io/jur/editorial-demo/`
6. جرّب مخطوطة افتراضية: الفحص الأولي، تعيين محكمين، تسجيل تقريرين، اختبار المنع عند اختيار revise، طلب تعديلات، استلام التعديلات (افتراضيًا)، تقريران جديدان، الترشيح، ثم التجهيز الخاص للنشر. اضغط **Reset fictional demo** لإعادة الحالة التجريبية.

**الموقع العام لا يقرأ أي مخطوطة حقيقية من `jus`، ولا يرسل أي رسالة أو ينشر أي مقال عند تجربة الإجراء.** يتم تخزين تغييرات تجربة العرض في متصفحك فقط.

## ثالثًا: المكوّن التحريري الخاص — اختياري وليس منشورًا

يحتوي الأرشيف التقني على `editorial-worker/`؛ وهو عامل Cloudflare مختلف تمامًا عن عامل رفع المخطوطات `uj-orh-submissions` الموجود لديك. **لا ترفع هذا المجلد داخل `docs/` ولا تفعّله قبل حماية Cloudflare Access.**

المتطلبات قبل النشر التجريبي:
- إعداد Cloudflare Zero Trust Access Self-hosted Application للعنوان الكامل لعامل `uj-orh-editorial` مع سياسة دخول محصورة بعناوين المحررين المصرح لهم، وتفعيل حماية متعددة العوامل حيث أمكن.
- نسخ قيم `ACCESS_TEAM_DOMAIN` و `ACCESS_AUD` و `ADMIN_EMAILS` إلى ملف `editorial-worker/wrangler.toml` محليًا. القيم النموذجية الافتراضية تجعل العامل مغلقًا.
- تشغيل `npm install` و `npx wrangler deploy` من داخل `editorial-worker/` فقط بعد نجاح ضبط Access، ثم إضافة `GITHUB_TOKEN` عبر `npx wrangler secret put GITHUB_TOKEN` **من دون وضع التوكن في GitHub أو هذه المحادثة**.
- التحقق من رفض الدخول في نافذة خاصة غير مسجّلة، ثم اختبار الحساب المصرح له باستخدام بيانات مخطوطة **خيالية وغير حساسة**.

العامل الخاص لا ينشئ صفحة منشورة، ولا يمس المخطوطة أو ملفات PDF المخزنة؛ بل يحفظ قرارات وملاحظات الإدارة في `submissions/<ID>/editorial.json` داخل `jus`، ويتحقق من صلاحية الوصول إلى المستودع الخاص.

## خامسًا: حدود الإصدار العلمية والأمنية

- لا يوجد **تقييم علمي حقيقي بواسطة AI** حتى الآن، بل نموذج فحص وتقييم بشري محاكٍ.
- هوية المحكمين في العرض وفي المكوّن الخاص لا تزال **تُدخلها الإدارة**؛ ولم ننفذ دعوات وموافقات محكمين مستقلين أو إدارة تضارب المصالح. لذلك لا يمنح النظام شهادة تقييم معتمدة؛ بل يسجل *مرشح اعتماد أولي*.
- لا يوجد نشر آلي للملفات من `jus` إلى `jur`، ولا DOI أو نظام تراخيص ونسخ محفوظة معتمدة.
- لم تكتمل المراجعة الأمنية/القانونية المؤسسية؛ لذا لا ينبغي دعوة باحثين لإيداع بيانات طبية مُعرِّفة أو مخطوطات سرية دون ضوابط تنظيمية مناسبة.
- الترقيم الحالي تجريبي على GitHub؛ عند التوسع يجب استخدام قاعدة بيانات مخصصة وتصميم صلاحيات المحكمين وسجل أحداث غير قابل للتلاعب بصورة أقوى.
- الحقوق المؤسسية: هذا مشروع توضيحي مقترح **وليس خدمة رسمية معتمدة من الجامعة الأردنية**.
