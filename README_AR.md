# إصلاح اتجاه العربية على أجهزة Android — v3.1.4

## النتيجة التي استند إليها الإصلاح
أظهر تقرير هاتفك أن الواجهة تحتوي على 421 عنصرًا قبل تبديل اللغة وبعده، وأن `main` بقي مرئيًا، لكن عرض المستند ارتفع من 338 إلى **10,254 بكسل** عند تطبيق RTL على جسم الصفحة. لذلك المرجح أن الصفحة لا تُمحى بل تصبح خارج مجال الرؤية بسبب خلل في تخطيط/تمرير RTL.

## التعديل
1. تبقى جهتا `html` و`body` في الوضع LTR ثابتتين.
2. يطبَّق RTL على العناصر النصية العربية فقط باستخدام CSS (`body.lang-ar [data-i18n]`) دون قلب اتجاه الصفحة بالكامل.
3. إصلاح محاذاة الحقول والنصوص العربية؛ إضافة `overflow-wrap` وحماية لعناصر الشبكات.
4. إذا أصبح عرض المستند أكثر من ثلاثة أضعاف الشاشة وبحد أدنى 1200 بكسل، تُستعاد الإنجليزية تلقائيًا بدل ترك صفحة فارغة.
5. أسماء ملفات جديدة v3.1.4 لتجنب تضارب ذاكرة المتصفح.
6. صفحة `diagnostics-layout.html` تسجل العناصر المسببة للاتساع إذا عادت المشكلة.

## رفع الملفات الأربعة — `jur` العام فقط
- `docs/index.html` **استبدال**.
- `docs/assets/app-v314-20261124.js` **إضافة**.
- `docs/assets/styles-v314-20261124.css` **إضافة**.
- `docs/diagnostics-layout.html` **إضافة**.

احتفظ بنسخة من `docs/index.html` السابق. **لا تغيّر** `docs/config.js` أو `worker` أو `jus` أو `publications` أو `editorial-demo`. لا تحذف الإصدارات السابقة من JS/CSS؛ يمكن التراجع باستعادة `docs/index.html` السابق وحده.

## اختبار بعد رفع GitHub
1. افتح `https://izzatahmed.github.io/jur/` في Chrome من نافذة عادية دون حذف بيانات الموقع.
2. حوّل للعربية؛ تحقق أن المحتوى بقي ظاهرًا، ثم عد للإنجليزية خمس مرات.
3. جرّب فتح الموقع مجددًا. لا تُحفظ العربية بين الزيارات مؤقتًا بحسب سياسة v3.1.3.
4. إن استمرت المشكلة افتح `https://izzatahmed.github.io/jur/diagnostics-layout.html` وفعّل التحميل ثم التبديل وشارك التقرير دون بيانات خاصة.
